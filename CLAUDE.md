# Notes for Claude Code

This repository is a teaching exercise for a 45 minute workshop on RNA-seq
analysis. The person you are working with may have never written code. Several
of them are skeptical about using AI in science, with reason.

## Do not open these

- `solutions/` — the answer key and the reference analysis. Reading it removes
  the point of the exercise. Do not open it, do not read it to answer a
  question, and say so if asked to.
- `scripts/make_data.py` — the generator. It states in its own comments which
  genes were made to differ and what was built into the data. Treat it the same
  as `solutions/` until the attendee tells you they have reached Block 3. After
  that it is worth reading together.
- `docs/figure-standards.md` — the eight checks the attendee applies to your
  figures by hand in Block 3. Not secret: it is printed and handed to them. Do
  not read it and do not apply it unprompted. If your figures come back already
  compliant, Checkpoint D — one correction the attendee identified themselves
  rather than one you offered — cannot be met. When they send you their own list
  of what is missing, act on all of it; that is the intended route.

If you are asked which genes are truly differential, the answer is that you must
not look. Attendees compare against the key in Block 3 by running
`scripts/score_results.py`, which is the intended route.

## The data

- `data/counts.tsv` — 4200 genes by 16 samples. Columns: `gene_id`,
  `gene_symbol`, `gene_length`, then `S01` to `S16`. Raw integer counts.
- `data/sample_metadata.tsv` — `sample_id`, `condition` (control or treated),
  `replicate`, `batch` (A or B). Eight samples per condition. Batch is balanced
  across conditions.
- `data/gene_sets.gmt` — gene sets for enrichment. The membership was assembled
  for this exercise and does not reproduce a real pathway database. Do not
  describe these sets as if they were MSigDB or GO.

The counts are synthetic. Do not present biological conclusions drawn from them
as if they were real findings.

## Conventions

- Python only: numpy, pandas, scipy, matplotlib, statsmodels. No other packages,
  and no R.
- Write output to `results/`. Figures go in `results/figures/` at 300 dpi.
- The results table is `results/de_results.tsv` with the columns `gene_id`,
  `gene_symbol`, `mean_expression`, `log2_fold_change`, `pvalue`, `padj`.
  `scripts/enrich.py` and `scripts/score_results.py` both read that file.
- Set the matplotlib backend to `Agg` before importing pyplot.
- Prefer a saved script over a series of one-off commands. The attendee needs to
  be able to rerun the analysis without you.
- **American spelling throughout**, in prose, comments, filenames, variable
  names and gene set names alike. 


  The names that changed and that other files depend on:
  `results/normalized_counts.tsv`, `docs/02-exercise-visualization.md`,
  `checkpoints/02_filtered_and_normalized.py`. The gene set names in
  `data/gene_sets.gmt` and the `gene_sets` column of `solutions/answer_key.tsv`
  changed with them; both are generated by `scripts/make_data.py`, so rename a
  set there and regenerate rather than editing the data files by hand.

## How to be useful here

- When you make a methodological choice the attendee did not specify, say what
  you chose and why, and name the alternative. Filtering thresholds,
  normalization method, statistical test and multiple testing correction all
  count.
- Show real output. Do not summarize a result you have not run.
- If asked for a plan, give the plan and stop. Do not write the code as well.
- When you interpret the results biologically, distinguish what the files
  support from what you know about these gene symbols from elsewhere. Say which
  is which without being asked twice.
- Plain language. Many attendees are not native English speakers and many do not
  have a statistics background. Define terms the first time you use them.
